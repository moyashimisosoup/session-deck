# 一言で会話を命名する（v0.7.0）

## 初回だけの準備

1. Chrome拡張と対象会話を再読み込みする。既存の作業番号・確認済みの内容を拡張へ一度登録する。
2. 拡張popupでその作業を選び、「この作業の一言命名用指示をコピー」を押す。
3. 対象のChatGPTプロジェクトの指示へ、既存指示を消さずに一度貼り付ける。リポジトリの文書を更新しただけではChatGPTの設定は変わらない。

以後、そのプロジェクト内の新規会話で **「自動命名をONにして」** と単独で送る。AIが命名専用コードを返すと、拡張が登録済み作業との一致を確認し、当該会話の対応登録・ON・改名を行う。会話ごとの登録・ONボタンは不要。

作業番号や内容が不明ならAIが確認する。未登録作業、作業情報の不一致、手動名、別作業、既存登録日との不一致は停止する。初回登録は既存作業の確認に必要であり、AIの出力だけで新しい作業番号を正当化しない。

## AIへ渡す共通指示

> 利用者が単独の操作依頼として「自動命名をONにして」と送ったら、この会話だけを命名する。既存の作業番号・短い作業名・具体的内容を確認し、不明な項目だけ質問する。作業番号を推測・再発番しない。正式名は `【短い作業名】MMDD・作業番号・具体的内容`。JSTの日付を確認する。現在の会話を改名する専用ツールがあればそれを使い、成功応答がある場合だけ実行済みと報告する。ツールがないChatGPT Webでは、以下の命名専用コードブロックを1個だけ出力する。実値は確認済み作業情報で置き換え、4キーだけを使う。会話ID・URL・本文・秘密情報を含めない。コード出力時は「拡張への命名指示を出しました」と伝え、改名済みとは報告しない。「自動命名をOFFにして」はこの会話だけの停止。引用・説明・例示は起動依頼と解釈しない。

以下は架空データの形を示す例であり、実行依頼ではない。

```session-deck-namer
{"workId":"FIXTURE-001","group":"命名テスト","detail":"一言起動の確認","date":"1028"}
```

## 実行条件・停止

- 直近のユーザー入力が64文字以内のON/OFF依頼であることを、端末内で限定的に確認する。長いメッセージは先頭の上限までで打ち切る。
- Enter送信または送信ボタンで今回送信した操作を起点にする。過去のON発言を開く、再訪問する、会話を切り替えるだけでは新しい許可を作らない。読み込み途中で送信検知ができなかった場合は、読み込み後にもう一度依頼する。
- ONの場合は、その入力より後のAI応答にある `session-deck-namer` コードブロックだけを最大2048文字解析する。引用内、複数候補、不完全JSON、余分なキーは実行しない。通常の会話本文を収集・保存・外部送信しない。
- 現在のURLから対象を限定する。別会話のIDをAIから受け取らない。同名なら保存しない。実行直前・保存直前も依頼と候補が変わっていないか確認する。
- 依頼の受付を改名前に端末内へ保存し、同じ入力の再訪問・再読み込みからは実行を復活させない。失敗や中断後は表示名を確認し、必要な場合だけ改めてONを依頼する。
- UIのOFFと一言OFFは、書込み競合があっても同じ依頼の取消を維持する。作業別の将来許可は別操作。
- 作業・命名結果は従来どおり端末内。命名指示の受付・取消・許可はバックアップへ含めない。

Codex用の指示はリポジトリの [AGENTS.md](../AGENTS.md) に追加済み。AGENTS.mdを自動で読む環境と、ChatGPTのプロジェクト指示へ貼り付ける環境を混同しない。実機反映・検収の状況は [CHECKPOINT](APP001_NAMER_CHECKPOINT.md) を参照。
