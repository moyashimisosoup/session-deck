# 「アプリ思いつき作成」プロジェクト共通指示への手動追記

これは**ユーザーがChatGPTのプロジェクト設定へ貼り付けるための短文**です。GitHubのファイルを作っただけでは現在・過去・将来のチャットの設定は自動変更されません。

## 貼り付ける文章

> アプリ開発の実作業回答の末尾に、原則「◦ APP-ID/作業領域｜状態｜確認したJST時刻（出所）｜証拠｜次の1操作」を1行だけ示す。長い状態報告を毎回繰り返さず、重要な決定・Gitコミット・PR・CI/公開の確認・担当変更時は、目的、登録済みwork_id、現行Repoとbranch/HEAD、保存・検証済み根拠、未保存、未確認、次の一手を短くCHECKPOINT化する。前回記録から重要な進捗が2〜3件重なったとき、過去の決定との混線が起きたとき、次の大きな作業を始める前、会話が長くなったと判断したときにはHANDOFF_READYを検討し、文脈喪失より早めに新チャットへの移行を提案する。2〜3件は運用上の注意目安であり、ChatGPTのコンテキスト残量・残り往復数を意味しない。取得不能な開始・終了時刻やコンテキスト％、他AIの稼働や担当者を捏造しない。チェックポイントは可能なら権限のある非公開Session Deck記録先に保存して読戻す。保存不能なら「未保存の引継ぎ」と明記する。新セッションはまずGitHubの最新HEAD・PR・CIを照合し、同一作業を重複実装しない。公開Repo・Pagesに実チャットURL・非公開セッションID・秘密情報を残さない。TradingSystem固有の実測コンテキスト監視・安全規則は引き続き優先する。

## 反映手順

1. ChatGPTの**「アプリ思いつき作成」プロジェクト**を開く。
2. プロジェクトのメニュー（プロジェクト名の横の `…` など）から**プロジェクトを編集／プロジェクトの指示**に進む。実際の名称は端末とアプリの版によって異なる場合がある。
3. 既存の指示を消さず、末尾に上の引用段落を**1回だけ**追加。すでに同等の「毎回の進捗バー」「チェックポイント」指示があれば重複する行をまとめる。
4. 保存後、テストチャットで「このプロジェクトの1行進捗・早期引継ぎ規則を確認して」と依頼し、**長い管理報告ではなく末尾1行が出る**ことを確認。
5. 作業を継続中の古いチャットには、必要に応じて「共通指示の早期引継ぎ規則をこのチャットから適用して」と短く送る。既存チャットへの反映を保証された挙動として扱わない。
