# ChatGPT 早期チェックポイント・予防的引継ぎ v1.1

適用: 「アプリ思いつき作成」など、ChatGPT上で進める非ローカルのアプリ開発作業。2026-10-17制定。
状態: **運用規則**。ChatGPTのコンテキスト残量の自動監視・別チャット自動生成・無人イベント保存を実装したという意味ではない。
既存契約: [CLOUD_SESSION_PROTOCOL.md](CLOUD_SESSION_PROTOCOL.md)／[CHAT_PROGRESS_BAR.md](CHAT_PROGRESS_BAR.md)。

## 運用目標と能力上の限界

上限に達して作業中の文脈を失うよりも早く、**GitHubの正本と短い引継ぎ記録から別チャットで再開できる状態を作る**。通常ChatGPTの残りコンテキストトークン、モデルの真の残容量、残り往復数、他セッションの稼働状態、開始・終了時刻は、確認できない限り**未確認**。警告の発生を保証したり、残量％の推定値を表示したりしない。

## 三層の復元経路

1. **GitHubが開発の正本**：コミット、PR、コード、仕様、CI、配信状態。新チャットは必ず現時点のHEAD/PR/CIを再確認。
2. **Session Deck非公開イベントがしおり**：APP-ID、登録済みwork_id、重要な判断、次の一手、確認済み証拠、CHECKPOINT／HANDOFF。本人に許可された非公開保存先のみ。保存後に読戻しするまで「保存済み」と言わない。
3. **チャットは作業の場**：各実作業回答末尾の1行ステータスは利用者向け表示であり、永続化ではない。非公開ストアへ書けなければ「未保存」の引継ぎメモをチャットへ出す。

## 事前チェックポイントの発動条件

| 段階 | 根拠にできるきっかけ | 必ず確認すること |
| --- | --- | --- |
| CHECKPOINT | 大切な裁定・原典照合・Gitコミット・PR・CI/公開確認、担当変更など | 再開に必要な確定事項、証拠URL、未保存、次の1操作を10〜20行程度に短縮し記録 |
| CHECKPOINT鮮度確認 | 最終チェックポイント以降に重要な進捗が**2〜3件**続く、対象領域が増える | 前の復元記録が現在のHEADや決定に追いついているか再確認 |
| HANDOFF_READY | 過去の決定の再確認が繰り返される、矛盾や文脈の混同が見える、これから長い作業を開始する、ユーザーが交代を希望 | 仕事を安全な区切りまで進め、根拠付きHANDOFFを作り、必要ならチャット移行を提案 |
| ROTATE | 引継ぎが保存・読戻しできた（または保存不能を明記した手元用メモができた）、次の作業に進める区切りに達した | 新チャットへ再開指示を渡す。現チャットを終了済みと記録するのは本人が区切りを指定したときのみ |
| 緊急FALLBACK | 会話が続けにくい、過去の情報が取得できない、API・ツール・コンテキスト関連の処理で失敗が増えた | 確認できたGit事実、未確認・未保存事項、次の1操作のみを即座に提示。失敗した保存を成功扱いしない |

**2〜3件は「作業が進んだ」ことの注意目安であり、トークン数の比率ではない。** 毎回の質問や雑談で長い進捗報告を繰り返さず、短い1行バーだけを使う。小さな作業の途中でむやみに中断しない。

## CHECKPOINT／HANDOFFの最小形

```text
CHECKPOINT / 観測したJST時刻: ______ / 保存状態: 読戻し確認済み・未保存
APP-ID: ______ / 領域: ______ / work_id: 登録済みIDまたは未割当
目的: ______
正本GitHub: ______ / branch: ______ / HEAD: ______（未取得は未確認）
確認済み成果と証拠: Commit / PR / CI / Pages / 実機確認を区別
未実装・未検証・未保存差分: ______
重要な決定と根拠: ______
次に実行する1操作: ______
新チャットへの指示: 最初にGitHubの現在HEAD・PR・CIを取得し、古い記録との違いを照合。重複実装を避ける。
```

大きなコンテキストを消費する会話全文・過去ログ・テスト全出力を貼り直さず、参照URLと判断だけを残す。

## セッション切替時の「再開ゲート」

- **取得したものだけ**START/END時刻・保存時刻・最終観測時刻を表示。GitHubのpush時刻をチャットの終了と解釈しない。
- 現在のGitHubのbranch/HEAD、PR/CI、公開URLを再取得。古い引継ぎに「完了」とあっても再検証。
- 同じwork_id・編集中ファイルへの別AIの作業を確認してから書込む。未コミット差分が取得できなければ、見えていないことを明示する。
- 公開GitHub Pages／公開Repo／PR／Issueには私的なセッションID、実会話URL、トークン、未公開のソース、内部引継ぎの全文を置かない。
- 他チャットの新規作成、チャットタイトルの自動変更、非公開Driveへの無人保存、実測不能な残量監視を実装済みと偽らない。

## Claude Code・Codexとの関係

実測のcontext window・使用量にアクセスできる環境では、採用済みのTradingSystemのCHECKPOINT / HANDOFF_READY / ROTATION_DUE段階を優先する。**ChatGPT通常チャットには同じ数値閾値を当てはめない**。

設定用の短い追記文は [CHATGPT_PROJECT_INSTRUCTIONS.md](CHATGPT_PROJECT_INSTRUCTIONS.md)。ユーザーがプロジェクト共通指示へ貼り付けて初めて適用範囲が広がる。すでに進行中の重要なチャットには必要に応じて適用を明示する。
