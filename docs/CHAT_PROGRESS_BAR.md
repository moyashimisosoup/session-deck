# Chat Progress Bar v1.0：全アプリ開発チャットの1行進捗

更新：2026-10-17 JST  
対象：プロジェクト「アプリ思いつき作成」のChatGPT・Claude Code・Codexで行う**実作業チャット**。TradingSystem固有の監視・安全指示は従来どおり優先する。

## 1. 既定表示：本文の最後に1行だけ

```text
◦ APP-007/koten:conj｜状態:検証待ち｜確認:10:42 JST｜根拠:PR #118｜次:差分とCIを照合
```

- **アプリ**：分かるなら`APP-ID/name:area`。対象不明なら`未照合`。実作業の`work_id`が登録済みのときだけ付ける。
- **状態**：`構想・設計・実装・検証・PR待ち・公開確認・保留・引継ぎ`等、根拠に一致した短い語。動いていることを推定する「稼働中」の多用を避ける。
- **時刻**：時計・ログ・コミット等の**出所が分かる最終観測・最終記録日時**。必要なら`JST（観測）`、`JST（保存）`と明記。分からなければ`未取得`。開始・終了を推測しない。
- **根拠**：実在するPR・commit・CI・書込読戻し記録への短いリンク／識別子。保存未確認なら`未保存`。
- **次**：作業者が実際に行う具体的な一手を**ひとつ**。`PRレビュー`や`GitHubのmainを読む`など行き先も示す。

1行が長いときは最初に`作業/状態/次`を優先し、時刻や根拠を省略せずに短縮する。通常の簡単な質問・雑談・安全上の難しい相談には無理に開発進捗を付けない。ユーザーが「毎回答の末尾」と指定する個別作業ではこの表示を既定とする。

## 2. 大きな進捗カードは節目だけ

START、MILESTONE、CHECKPOINT、HANDOFF、END等で必要な場合だけ以下を表示する。

```text
APP-007 / APP-007-Wnnnn（未割当なら未割当）
推奨チャット名: 〖古典・conj〗1017・01・活用ヒント配置
開始: 未確認 ／ 最終記録: 2026-10-17 10:42 JST（保存確認済みの場合のみ）
現在: PRレビュー待ち ／ 公開: 未確認
次: PR #118 の差分とCIを再確認
```

「作業中」「コード完成」「GitHub保存」「公開」「iPhone実機確認」を区別する。書込み失敗なら`未保存`と記録する。進捗％・モデルの残コンテキスト％は実測情報がなければ表示しない。

## 3. ChatGPTプロジェクト共通指示への最小追記（貼り付け用）

以下はユーザー自身がChatGPTのプロジェクト設定に追記するための文面。**このGitHubファイルの作成だけではChatGPT全セッションに設定が自動反映されません。**

> アプリ開発の実作業チャットでは、原則として各回答の末尾に「◦ APP-ID/作業領域｜状態｜確認したJST時刻（出所を区別）｜根拠｜次の1操作」を**1行だけ**示す。作業IDは登録済みのものだけ使用。GitHubの最終コミット時刻・チャットの開始終了・最後の観測を混同せず、取得不能は未確認とする。長い進捗・引継ぎは重要な状態変化時にだけ記録し、存在を確認したGitHubと権限のある非公開Session Deck保存先を正本とする。推測の進捗率・残コンテキスト割合・稼働中判定を表示しない。会話の本題を進捗表示で圧迫しない。

## 4. モデルごとの適用方法

| 実行環境 | 自動適用可能な部分 | 未自動化 |
| --- | --- | --- |
| ChatGPT通常チャット | プロジェクト共通指示の追記で回答様式を促す（このチャットでは今から適用） | 全チャットの自動改名、開始/終了日時・コンテキスト利用量の取得、Driveへの無人保存 |
| Codex（Repo） | Repo root `AGENTS.md`の規則を作業環境が読めるとき適用 | GitHubの外で始めたチャットへの自動遡及 |
| Claude Code（Repo） | Repo root `CLAUDE.md`で作業規則を案内 | 全作業での無人同期、実セッション終了推測 |
| Session Deck | 公開GitHubのAPP-ID・PR/CI/コミットと、許可済みの非公開イベントを**区分して**追跡 | 現在の公開Pagesがprivate Driveへ直接ログインして実イベントを閲覧するUI |

## 5. コンテキスト飽和対応

- **長時間の実作業**：変更・未保存差分・GitHub HEAD/PR・受入検査・次の操作を少量のCHECKPOINTに残す。
- **セッション交代**：HANDOFFの要点だけを次セッションに示し、最新HEAD/PR/CIを再確認。旧資料の巨大なコピーをしない。
- **TradingSystem**：実測のコンテキスト量があるClaude/Codex監視では既存`CHECKPOINT/HANDOFF_READY/ROTATION_DUE`を優先。
- **ChatGPT**：コンテキスト使用率を取得できない限り具体的％を出さず、ユーザーが移行を希望したとき・重要な区切り・長文作業の終盤でチェックポイントを作る。

## 6. kotenの導入例

- APP-007の公開コード：`yama-books/koten`。
- 設計・内部調整：アクセスを許可された`moyashimisosoup/koten`。
- 同一Repoに`hyakunin / conj / vintage-kana / checkpoint`があるので、ステータスの対象領域を省略しない。
- 同じ`work_id`への同時書込を防ぐ。公開PRの状態が分かっても担当セッションが動いていると勝手に断定しない。
- 巨大なHANDOFF歴史の全文を毎回読み込まず、担当領域の最新の該当節だけ参照する。
