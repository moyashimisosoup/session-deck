# Session Deck 命名操作 v1 導入手順・安全境界

- 作業ID: NAME-01 / NAME-02
- 版: 0.1 / 2026-10-17 JST
- 対象: Session Deck, ChatGPT Web, ChatGPT iOS, Claude Code, Codex CLI
- 状態: 実装済みの機能と本番実機未検証の機能を明確に分離する

## 目的

命名規則 `【短い作業名】MMDD・作業番号・具体的内容` を共通化し、AIサービスごとのチャットに適用する。`work_id`は原則、既存作業台帳で管理している値を用いる。IDを勝手に再発番しない。

## 最短の使い方（PC/iPhone共通）

1. Session Deckの `naming.html` を開く（Pages公開後は https://moyashimisosoup.github.io/session-deck/naming.html ）。
2. 「短い作業名」「MMDD（JST）」「作業番号」「具体的内容」を確認して編集。
3. ChatGPTの場合は「正式名をコピー」を押し、対象チャットのメニューから「名前を変更」に貼る。
4. Claude Code / Codex CLIの場合は「/renameをコピー」を押し、**現在の正しいセッション**に入力して確定する。
5. 各サービス上の表示名を読み戻して一致を確認する。

本ツールは**名前の生成・コピーを行うだけ**。iPhone ChatGPTネイティブアプリの画面へ介入せず、自動で改名成功を主張しない。Clipboard APIが使えないブラウザでは手動コピー画面を出す。

## 非ローカルChatGPT会話への対応（v1：手動で対象を開く）

Session Deckの命名コンソールは、iPhone・PCからChatGPTの保存済み会話にアクセスするための補助を提供する。**会話URLの入力は任意**。指定したURLのホスト名とパスを検証し、個別会話（`https://chatgpt.com/c/...` またはプロジェクト配下の会話）のみを別タブで開く。共有リンクは対象外とする。URL内のクエリとフラグメントは取り除く。入力したURL、ID、タイトルは**送信・保存・自動同期しない**。

会話の中身や一覧をChatGPTから直接取得できるわけではない。対象会話が同一アカウントで表示できること、貼り付けた正式名を設定したこと、改名結果を再度開いて確かめることは利用者側で確認する。PC Webの補助は後述の試験用拡張、iPhoneはWebやネイティブアプリの手動改名UIを利用する。

本格的な非ローカル連携（多数の会話メタデータの登録と端末間同期）は別設計とする。認証済み非公開ストア、最小データ保持、権限検証、削除/撤回、暗号化、取得元と観測時刻、会話の本人一致検証を満たすまでは公開PagesやGitHubに実ID/URLを書かない。ChatGPTの通常履歴を列挙・改名する公式APIが提供される前提で実装しない。公式データエクスポートは参照用の将来候補であり、機微な会話本文を含むので公開サイトへの一括アップロードは禁止する。

## PC ChatGPT Webで一歩進める（拡張機能・手動1クリック）

`extensions/chatgpt-namer`に、Chromiumブラウザ拡張（Manifest V3）のソースを格納する。

インストール（ブラウザごとに必要）:

1. GitHubの`Code → Download ZIP`でリポジトリを取得し展開する。GitHubリポジトリの**ブランチは導入予定の版（レビュー後はmain）**であることを確認。
2. Chromeなら`chrome://extensions`、Edgeなら`edge://extensions`を開き、開発者モードを有効にする。
3. 「パッケージ化されていない拡張機能を読み込む」から`extensions/chatgpt-namer`フォルダを選ぶ。
4. `chatgpt.com`で**テスト用の保存済みチャット**を開き、必要ならサイドバーを開く。初回はページをリロードする。
5. 命名コンソールで正式名をコピーし、拡張機能ポップアップの入力欄に貼る。
6. 「この会話の名前を変更」を押す。成功表示が出ても**画面上の表示名と再読み込み後の持続性**を目視確認する。

保護:
- 現在開いている`/c/<session_id>`を照合し、別チャットに変わっていたら停止する。
- 画面上の対象行/メニュー/編集欄を**一意に特定できなければ実行しない**。
- 入力名が規則外なら拒否する。
- 明示ボタンクリックが起点。自動・一括改名、全履歴巡回は行わない。
- 画面上で更新名が観測できた場合のみ`verification: ui_observed`をブラウザの`chrome.storage.local`へ保存。これはサーバーへの永続化確認ではない。
- Cookie、トークン、APIキー、会話本文は取得・送信しない。ネットワークAPIへのリクエストは行わない。
- Chromeの仕様変更で動かなくなった場合、無理に未知のメニューを操作せず、ChatGPT本体の手動改名へ戻す。

### 実機検証に基づく v0.3 修正（2026-10-19）

ユーザーのChromeで **会話IDと表示名の取得成功**、改名メニュー検出の失敗を確認した。原因は本番DOMを直接取得できず未確定だが、従来の検出が見た目のテキストと §role=menuitem§ のみに依存していた。対応として日本語・英語の別表記、ARIA名、Radixメニュー属性、会話行内の専用オプションボタン、インライン編集欄のEnter確定を追加した。対象会話のIDは操作前、メニュー表示後、確定時に照合し、重複する改名候補はクリックしない。

**既にv0.2をインストールしたPCの更新手順**:
1. GitHubの§main§へ修正が反映された後、手元の §D:\dev\session-deck\extensions\chatgpt-namer§ 内の4ファイルを同じ最新版に更新する。Gitの§pull§でもよい。古い§content.js§と新しい§manifest.json§を混在させない。
2. Chromeで§chrome://extensions§を開き、Session Deck Namer（v0.3.0）の「更新」または「再読み込み」を押す。§chatgpt.com§のテスト用会話ページもリロードする。ZIPの再インストールは不要。
3. テスト会話のサイドバーを開き、ポップアップで会話ID・表示名を確認。正式名を入力し、1件だけ改名する。
4. 改名後の表示名を確認し、さらに§F5§で再読み込み後も同じ名前であることを確認する。
5. 失敗時は拡張画面の**エラー文全文と、チャット本文を隠したメニューのスクリーンショット**を共有する。診断に使用するのはUIメニュー項目の件数と候補件数だけであり、チャットの中身・認証情報は採集しない。

自動メニュー検出が失敗する場合、チャット本体のUIから手動改名できる状態を維持し、それ以上不明なボタンを押さない。インラインEnter送信のDOMイベントが本番のReact実装に受理されるかは**実機再検証待ち**。自動テスト成功だけでは実運用完了としない。

**重要**: 拡張機能の本番アカウント／実機での操作確認は未完了。拡張機能はストア審査済みアプリではなく試作であり、インストールにはユーザー操作が必要。

### v0.3.1: type属性がない改名入力欄への対応（2026-10-22）

実機の「チャット名を変更」ダイアログは入力欄の `type` 属性を省略している。v0.3.0は `input[type="text"]` だけを探すため、開いている入力欄を見落とし、背後のメニューボタンの探索へ戻って停止した。v0.3.1はDOMの `input.type` が `text` の入力欄を数え、候補が1個の場合だけ採用する。明示的なtext入力欄とtype省略の入力欄が両方ある場合も、重複として停止する。

この修正は入力欄の検出だけを対象とする。拡張から最初にメニューを開く段階の失敗は別途実機確認が必要。導入時は4ファイルを同一版で更新し、拡張の再読み込みとテスト会話ページの再読み込みを行う。切り分けでは本体UIで改名ダイアログを開いてから拡張の明示ボタンを1回押し、画面上の表示名と再読み込み後の保持を確認する。自動テストの成功だけでは実機成功としない。

## Claude CodeとCodex CLI

両製品とも対話モードで`/rename <name>`が利用できる。命名コンソールのコピー用コマンドを対象のセッション内で実行すればよい。セッション識別子が同じでも、異なるアプリ/CLI間の表示名が必ず同期されるとは仮定しない。ユーザーが名前を設定したセッションは勝手に上書きしない。

今後の自動化では、Claude Codeの公式`SessionStart`の`sessionTitle`仕様を候補とするが、既存Hooksとの競合がないことを検証してから別の変更として導入する。Codexの非対話モードでの`/rename`動作や外部からの強制改名は想定しない。

### v0.3.2: 対象行とメニューの関連を照合

2026-10-22の専用テスト会話で、行コンテナの `data-sidebar-cycle-item`、起動ボタンの `aria-haspopup="menu"`、メニューの `aria-labelledby` / ボタンの `aria-controls` を観測した。対象行に会話リンクが1個だけあることをボタン探索より先に確認する。起動はArrowDownのキーボードイベントを使用し、当該ボタンに関連付いたメニュー内の改名項目だけを選ぶ。入力欄の現在値と対象行の名前が違う場合も停止する。

DOM構造の観測と通常のブラウザクリックによるメニュー表示は確認済み。拡張更新後のキーボード起動・保存・再読み込み保持は、まだこの版の実機検収待ち。自動テスト合格を実機成功と扱わない。

### v0.4.0: 作業登録と候補の再表示（実機検収待ち）

正式形式は引き続き `【短い作業名】MMDD・作業番号・具体的内容`。コンソールには拡張の `naming-core.js` と同じ処理を埋め込む。変更後は `node scripts/sync_naming_core.mjs` で同期し、テストで一致を検査する。Pagesへ拡張フォルダを配信する必要はない。

拡張のポップアップまたは画面右下の「作業の登録・選択」で、台帳の既存作業番号・短い作業名・具体的内容・MMDDを登録する。作業番号を自動発行したり、会話本文から推測したりしない。登録だけでは改名せず、登録済み作業から候補を表示する。「確認してこの会話を改名」の1回の明示操作で現在の会話だけを変更する。

会話ID確定、切替、戻る・進む、再読み込み、再訪問を、現在URLと対象行の定期照合で確認する。登録時の日付を維持する。別の作業、手動変更された名前、曖昧な対象は保護する。「対応を解除」で候補適用を止める。自動改名の許可機能はまだ追加せず、常に明示確認を要する。

既存の `sessionDeckNamerRecords` を残し、作業情報・対応・追加履歴を `chrome.storage.local` 内に保存する。作業情報や実会話のID・名前は非公開のままとし、公開GitHubに保存しない。画面確認は `ui_observed` であり、再読み込み後の保持は独立に確認する。

テスト22件成功と実機合格は別。導入後、専用テスト会話で登録→候補表示→確認→メニュー起動→保存→再読み込み→再訪問を検収する。

### Dドライブへの固定配置とローカルデータの移動

固定先は `D:\dev\local-env\session-deck\extensions\chatgpt-namer`。フォルダを変えると別の拡張IDになる場合があるため、まず旧拡張の同じ読み込み元をv0.4.1へ更新し、拡張の再読み込み後にポップアップの「保存データの移動」からファイル保存する。このJSONは非公開の会話ID・名前を含むのでGitHubへ保存しない。

D側を読み込み、同じメニューからJSONを読み戻して履歴・作業対応を確認する。競合するデータは上書きせず停止する。移行確認までは旧拡張を削除しない。旧拡張と新拡張を同時に有効にしてテストせず、旧側を無効にしてからD側の専用テスト会話で検収する。旧フォルダの削除はデータ引継ぎを確認した後に行う。


### 実機検収（2026-10-23 JST）

v0.4.1をD側の正本フォルダから導入し、保存データの読み戻し後、専用テスト会話1件で「作業登録→候補生成→確認ボタン1回→メニュー起動→入力・保存→ページ再読み込み後の保持→新規画面を経由した再訪問時の候補表示」を確認した。改名ダイアログの手動事前起動は不要だった。同じ表示名と候補が一致した状態では再適用ボタンが無効になった。登録日を固定するため日付跨ぎだけで候補は変えない。

検収は日本語UI・当該専用会話だけの実績であり、他のUI・多重タブ・全会話の動作を保証するものではない。条件付き自動改名は未実装・無効。GitHub保存・CI・Web公開の状態はCHECKPOINTで別に管理する。
